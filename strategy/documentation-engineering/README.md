# Documentation Engineering
**Version 0.1.0 · Proposed for pilot and human ratification.**

Make knowledge understandable, usable and navigable. [Reviewability Engineering](../reviewability-engineering/README.md) makes the same artifacts inspectable, verifiable and governable. Both share one verification report, bounded correction loop and human approval process. Neither changes product intent or adds SDLC stations.

Start with purpose and first principles; explain the whole in roughly two pages or less, then reveal necessary details. Compare related concepts, use MTS implementation-specific examples, and use human anatomy/physiology and traditional computing analogies where they clarify. Preserve canonical visual sources and distinguish examples from evidence.

The existing four review depths remain unchanged. Reading depth within a document is independent of review depth. The governing strategy's station artifact hierarchy is also distinct.

**Adoption:** pilot on Product, Architecture, Definition of Done and Factory; compare with approved baseline, evaluate both standards, refine, obtain explicit approval, then enable default enforcement. Proposed guidance does not supersede existing adopted rules.
