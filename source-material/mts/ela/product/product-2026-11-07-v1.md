## 1. Executive product picture

**Promise.** Convert approved ELA learning intent into reliable, differentiated, print-ready teaching, practice, assessment, and reference materials, with defensible solutions and independently inspectable quality evidence.

**In simple terms:** A teacher specifies the learners, the skill, and the purpose. The product finds or creates suitable content, builds the appropriate material, supplies the requested level of answer support, verifies it, and stages it for a human-authorized release.

**Users:** MTS curriculum owner, teachers, students, content reviewers, release operators, and future school/program partners.

**Outcomes:** comprehension and vocabulary transfer; stronger writing/grammar application; consistent teaching materials; reduced preparation/rework; source integrity; reliable answers; usable printing; auditable releases.

### Product configuration dimensions

| Axis | Supported scope | Key distinction |
|---|---|---|
| Learning domain | Reading comprehension; vocabulary; grammar/language conventions; writing/composition; integrated ELA | Each domain has its own pedagogical rubric |
| Delivery purpose/type | Weekly practice; mock/benchmark test; classwork; homework; single-topic practice; revision/remediation; diagnostic; enrichment | Purpose drives scoring, scaffolding, and format |
| Source mode | Ready-made, source-faithful; raw source transformed into assessment; original AI-generated; approved hybrid | Provenance and transformation policy differ |
| Student artifact | Worksheet, test paper, class handout, guided activity, practice set, passage/question packet | Not every artifact needs a passage |
| Teacher/answer artifact | Key only; key + concise rationale; worked solution; MTS method-based teaching solution (e.g. PQYA/YPQA); rubric/model response | Depth depends on task and audience |
| Instruction/reference artifact | Lesson plan, topic overview, study notes, cheat sheet, formula/rule/reference sheet, worked examples | Teaching assets may be produced without a worksheet |
| Print/delivery profile | 2-page target, 4-page or longer approved profile, multi-column, font/scale/spacing policy, PDF and editable source as appropriate | Targets are configurable, never excuses for unreadability |
| Run context | Grade/band, date/week, curriculum objective, topic, difficulty, assessment mode, source constraints, release destination | Explicit run contract controls variants |

**Product composition:** `Learning Domain × Purpose × Source Mode × Artifact Set × Answer Mode × Presentation Profile × Grade/Run Contract`. This is a configurable combination space, **not** a promise that every combination is immediately implemented.

### Value stream

`Learning intent → Curriculum/content specification → Source selection or authoring → Assessment and teaching assets → Independent verification → Human approval → Publication and coverage tracking → Observations and improvement`.

**Inputs:** approved date/grade/topic, learning outcomes, audience, purpose, source rights and constraints, selected production profiles, answer method, output and publication settings.  
**Outputs:** selected student and teacher materials, source register/manifest, QA results and evidence, approved release record, updated coverage and learning register.

## 2. Scope and offering catalog

### Learning domains

- **Reading comprehension:** literary and informational prose, poetry, passage-based reasoning, main idea, inference, evidence, author's purpose/tone, structure, figurative language, vocabulary in context and cross-text analysis where appropriate. Preserve accurate passage line references.
- **Vocabulary:** context inference, meaning precision, usage, morphology/roots, semantic relationships and transfer into authentic reading, writing and speaking. Reading comprehension remains the primary outcome, memorized definitions are not the main goal.
- **Grammar and language conventions:** punctuation, sentence structure, parts of speech, clauses, usage, tense, editing, mechanics and stylistic application.
- **Writing:** sentence-to-paragraph-to-essay tasks, narrative, informative and argumentative writing, organization, evidence, revision, editing, exemplars and scoring rubrics.
- **Integrated ELA:** combined reading, vocabulary, grammar and writing tasks tied to a common text or objective.

### Worksheet and assessment modes

| Mode | Intent and expected variation |
|---|---|
| Weekly worksheet | Continuity from Curriculum Manager; explicit grade/week scope; balanced practice |
| Mock / benchmark test | Test-like instructions, timing/scoring where specified, source-faithful question selection and answer mapping |
| Class worksheet / guided practice | May include teaching cues, scaffolds, examples and class discussion tasks |
| Homework | Independent instructions, self-contained student material, appropriate difficulty |
| Single-topic worksheet | Deep practice on one concept, e.g. commas, quotations, inferences, verb tenses |
| Diagnostic / remediation | Identify errors, target gaps, support reruns and differentiated follow-up |
| Revision / enrichment | Mixed retrieval, cumulative challenge, advanced transfer and extension |

These are **purpose profiles**, not separate generation engines. The same topic can appear in weekly, class, homework and mock modes with different constraints.

### Source modes and fidelity contract

1. **Ready-made source:** extract or faithfully reproduce approved passage/questions/key; preserve content and original mappings when requested; source location and authorization recorded; re-render only when the approved mode permits it.
2. **Raw source:** select excerpts from a book/article/poem or provided text, then construct questions, explanations and teaching assets; verify text fidelity, rights, excerpt location and line numbering.
3. **No external source / AI original:** generate original instructional or passage content; label origin clearly and verify correctness, grade fit and originality claims appropriately.
4. **Hybrid:** combine sources and/or original content only when explicitly approved and attribute each segment.

Missing or unauthorized sources are blockers or controlled alternatives—not a license to silently substitute material.

### Answer and teaching-support modes

- **Answer only:** answer letters, brief responses or accepted responses with exact student-item correspondence.
- **Key with explanations:** correct answer plus concise why and relevant text/rule evidence.
- **Worked solution:** stepwise explanation, alternative reasoning and distractor analysis where valuable.
- **MTS method-based solution:** approved PQYA/YPQA reasoning structure, including poetry-enhanced analysis and explicit evidence; named methods and rubrics are versioned, not guessed.
- **Writing evaluation:** sample/model response, analytical rubric, scoring dimensions and feedback; distinguish model answers from uniquely correct answers.
- **Teacher lesson support:** topic explanation, example/nonexample, common misconceptions, guided practice, independent practice and optional checks for understanding.

### Presentation and publishing

- Student and teacher artifacts are separate when requested and always synchronized to one canonical content/selection manifest.
- A **two-page target** for weekly student worksheets and teacher keys is retained from v1.1; 4-page, one-page or longer profiles may apply to different products. Actual page caps, typography, columns, margins, scale and font sizes must be set by a versioned product/grade/profile policy.
- Favor readability, complete questions and consistent MTS visual identity over aggressive shrinking; record approved exceptions.
- Validate final exported pages for clipping, unexpected whitespace/overflow, orphaned text/choices, incorrect headers, line references and key correspondence.
- Dated, mode-aware filenames; editable artifacts when useful; PDFs for print; release manifest and accessible QA reports. The preferred QA experience is a human-readable expandable report, with printable PDF and structured evidence as complements.

Other types (e.g. grammar lesson notes and mock tests) have precedent, but their full end-to-end automated verification and breadth are **not** asserted as complete. ## 4. Product-wide controls and success measures

**Non-negotiables retained from v1.1:** curriculum/run contract is authoritative; out-of-scope grades are visibly separate from unverified checks; source provenance is recorded; independent semantic review cannot be replaced by an author validating its own output; exact student/key item matching; inspect exported print, not only markup; all required QA gates pass or approved exceptions are recorded; a named human explicitly authorizes publication; publication is remotely reconciled; learnings drive regression tests.

**Proposed measurable outcomes** (targets, not claims of observed performance):

| Outcome | Measurement direction |
|---|---|
| Educational validity | 100% of released assessable items independently checked for correctness, ambiguity and evidence/rubric fit |
| Scope fidelity | 100% coverage of active approved objectives and artifacts, or explicit exceptions |
| Source integrity | 100% of externally sourced excerpts/items have provenance and verified fidelity/permissions status |
| Key synchronization | 100% of key entries map to the selected student items and selected answer mode |
| Print usability | 100% of published exports pass required visual/structural checks; profile-specific page targets tracked separately |
| Release integrity | 100% published packages have human approval, immutable manifest and publication reconciliation |
| Improvement | Track rework cycles, escaped defects, production duration, review effort and rubric gaps |

**Traceability:** `Outcome → Capability → Business process/rule → Requirement → Acceptance criterion → Verification group/criterion → Test or evaluation → Evidence → Gate → Released artifact`. Stable IDs and many-to-many mappings belong in detailed catalogs.

**Release gates:** G0 run and intent; G1 source/content; G2 semantic and teaching correctness; G3 exported artifact/print; G4 explicit human approval and publication reconciliation. Report `PASS`, `FAIL`, `NOT VERIFIED`, applicable skips and `OUT OF SCOPE` distinctly. Missing mandatory evidence blocks certification.

## 5. Authority, boundaries, and next decisions

**Product owner:** owns vision, supported offering catalog, priorities, educational goals and exceptions. **ELA reviewer/teacher:** owns educational sufficiency and interpretation. **Verification process:** provides independent evidence, with distinct automated and reviewer findings. **Human release approver:** authorizes each release after gates. **Release operator:** reconciles remote publication.

**Outside this product:** choosing goals on behalf of the teacher without approval; universal correctness claims for subjective writing/poetry; generating unselected grades; bypassing source permissions; implementing general-purpose orchestration, observability and evidence infrastructure separately inside ELA (these are shared-factory concerns).
