# MTS Software Factory

A reusable, model-agnostic, AI-native software factory, with MTS educational products as the first implementation domain—not the architectural boundary.

## Engineering method

M0–M8 stations connect intent, requirements, architecture, design, implementation, verification, delivery, observation, and learning. Human authority, atomic artifact IDs, traceability, evidence gates, and requirement-delta feedback are fundamental.

## Documentation standard

Authoritative Markdown artifacts begin with a decision-ready, holistic overview (normally 1–2 pages), supported by useful visuals, tables, or flowcharts, and then provide a clear drill-down into the complete content. Write in a plain-language, Feynman-inspired style: explain the whole and why it matters before details, make relationships visible, and clarify unfamiliar terms. The overview should support most routine human reviews without reading every detail; it is a review lens, not a replacement for the authoritative artifact. See the strategy’s [documentation standard](strategy/ai-sdlc/ai-sdlc-software-factory-strategy.md#documentation-standard-for-artifact-markdown).
